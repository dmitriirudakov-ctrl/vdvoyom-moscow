# Вдвоём

Мобильное приложение для идей и планов выходного дня в Москве. React + TypeScript + Vite, Supabase и GitHub Pages.

## Что работает локально

- Отдельная идея и план дня с обедом, бюджетом на двоих и резервом на транспорт.
- Бюджеты 2000, 3000, 4000, 5000 и 6000 ₽.
- Ручной выбор погодных условий, даты, категорий и времени старта.
- Замена одной остановки с проверкой оставшихся временных окон и стоимости.
- Личные и общие сохранения, ручная история, общие лайки и исключение мест.
- Открытие всего маршрута в Яндекс Картах, экспорт данных в JSON.
- Мобильный интерфейс, manifest и иконки для добавления на главный экран iPhone.

Без настроек Supabase приложение запускается в **деморежиме на одном браузере**. Роли «Я» и «Партнёр» демонстрируют сценарии, но не защищают локальные данные. Это не вход в настоящие аккаунты и не синхронизация между телефонами. Не используйте деморежим для личной информации.

При наличии настроек Supabase вместо деморежима показывается вход в закрытые аккаунты, а записи читаются и изменяются через RLS. Открытая регистрация не нужна.

## Запуск для разработки

Требуются Node.js 24 и pnpm 11.25.0.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Откройте адрес, который выведет Vite. Для этого компьютера подготовлен [отдельный запускатель](./START.command), который находит установленный в Codex Node.js. Запускатель не устанавливает системные программы.

```sh
pnpm test
pnpm build
pnpm preview
```

`pnpm test` проверяет генератор, даты Москвы, обработку источника и настоящие политики PostgreSQL RLS в локальном PGlite. Это не заменяет проверку размещённого Supabase Auth и двух реальных устройств.

Серверная функция проверяется отдельно командой `deno check supabase/functions/import-events/index.ts` (Deno 2). Эта проверка также включена в оба workflow GitHub Actions, поскольку сборка Vite проверяет только клиентскую часть.

## Подключение настоящих аккаунтов и синхронизации

Последовательность для владельца без опыта программирования описана в [инструкции подключения](./SETUP.md). Создание внешних аккаунтов и принятие их условий выполняет сам владелец.

1. Создайте бесплатный проект Supabase и примените [миграцию](./supabase/migrations/202610300001_initial.sql) в SQL Editor.
2. Отключите самостоятельную регистрацию. Создайте два пользователя и профили в одной паре. Для подготовленного интерфейса логин `name` соответствует служебному email `name@weekend.invalid`.
3. Укажите только URL проекта и **publishable key** в локальном `.env.local` по образцу `.env.example`. Устаревший `anon` key также поддержан. `service_role` и `sb_secret_*` запрещены в клиентской конфигурации; Vite проверяет это перед запуском и сборкой.
4. Войдите по двум аккаунтам из разных браузерных профилей и проверьте личное сохранение, обмен и общую историю.

Для владельца, который работает через терминал, есть `scripts/provision-couple.mjs`. Он читает JSON с настройками только через stdin, создаёт ровно два аккаунта и связывает их с одной парой. Секреты и пароли нельзя добавлять в команды, Git или чат. Скрипт не запускался против внешнего проекта.

Данные пары находятся в Supabase, а не в GitHub. Файл личного проектирования `WEEKEND_APP_PLAN.md` остаётся локальным и исключён из публикации кода.

## Афиша

Подготовлены серверная функция `supabase/functions/import-events` и расписание `supabase/cron.sql`. Функция:

- Принимает только POST с серверным секретом `IMPORT_SECRET`; из браузера не вызывается.
- Запрашивает афишу Москвы на 45 дней вперёд, проверяет координаты, категории и даты.
- Отделяет точную, минимальную и неизвестную стоимость. Нижняя граница «от …» не используется как полный бюджет посещения.
- Не выдаёт промежуток между двумя отдельными сеансами за доступность мероприятия каждый день.
- Заменяет снимок афиши атомарно; при ошибке сохраняет предыдущий. При успешном импорте удаляет события, которых больше нет в источнике.
- Сохраняет источник и ссылку на конкретное событие.

На этапе локальной разработки реальный запрос KudaGo вернул **HTTP 403**. Обработчик и нормализация проверены на фиксированных примерах; работа из Supabase ещё должна быть подтверждена. Нельзя обозначать эту интеграцию как действующую до успешного живого импорта. Временные события не выдумываются.

Предыдущая афиша имеет отметку времени обновления. События с уже прошедшей датой отфильтровываются, даже если импорт не сработал.

## Погода

Сейчас действует ручной выбор с кнопкой перехода в Яндекс Погоду. Автоматический режим **не подключён**. Персональный API Яндекса предоставляет прогноз только на сегодня и завтра, а допустимость его использования для двух аккаунтов требует подтверждения условий. Сбор страниц в обход API не предусмотрен.

Проверка горизонта реализована с датами `Europe/Moscow`, независимо от дня недели и часового пояса сервера.

## Качество каталога и стоимость

Начальная подборка содержит постоянные места с первоисточниками. Цены музейных билетов сверяются с указанными страницами; они всё равно могут измениться. Резерв для Третьяковской галереи и лимит на обед являются плановыми суммами, а не утверждением о текущей цене или среднем чеке. Бесплатное посещение общих пространств ГЭС-2 не означает бесплатный вход на все выставки.

Время в карточках — предложенный план. Если расписание не подтверждено, интерфейс просит проверить его перед посещением. Время перемещения приблизительное; оно не рассчитывается транспортным API. Между соседними остановками генератор ограничивает оценку дороги 45 минутами, от отправной точки допускается более дальняя поездка.

Используется консервативный внутренний многоугольник МКАД. Он подходит для отсечения заведомо внешних мест, но исключает часть пограничных территорий. Перед расширением каталога возле кольцевой дороги нужен точный контур с проверенным источником. Не считать этот файл геодезической границей дороги.

## Публикация

В GitHub подготовлены два workflow: проверки и ручная публикация на Pages. Публикация требует двух публичных настроек Supabase в Repository Variables; при их отсутствии workflow остановится, чтобы случайно не опубликовать демо вместо приложения с аккаунтами. Платный домен не нужен.

После первой публикации проверьте доступ с обоих iPhone, вход, личное сохранение, действие «Поделиться», ручную историю и экспорт. Бесплатный Supabase может приостановить проект после недели низкой активности; восстановление выполняется владельцем в панели.

## Резервная копия

Кнопка экспорта сохраняет доступные текущему аккаунту записи, общую историю и оценки. Поэтому для копии обоих наборов личных сохранений нужно выполнить экспорт из каждого аккаунта. Храните JSON вне открытого репозитория.

Восстановление проводится владельцем в Supabase: сначала создаются/проверяются пара и аккаунты, затем записи сопоставляются с их актуальными идентификаторами. Не загружайте экспорт под чужим `owner_id` и не открывайте административный ключ в браузере. Автоматический импорт резервной копии через интерфейс пока не реализован.
